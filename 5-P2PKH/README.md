 P2PKH交易脚本验证

实验目的
1. 理解ScriptSig与ScriptPubKey
2. 理解堆栈脚本执行机制
3. 理解P2PKH交易验证流程

ScriptSig
<Sig> <PubKey>

ScriptPubKey
OP_DUP OP_HASH160 <PubKeyHash> OP_EQUALVERIFY OP_CHECKSIG

学生任务
1. 构造解锁脚本
2. 执行脚本堆栈
3. 验证签名

实验原理
1. 比特币堆栈式计算引擎核心</br>
比特币交易验证依赖“堆栈式虚拟机（Script VM）”，核心是后进先出（LIFO）堆栈，执行流程：解析交易脚本（解锁脚本+锁定脚本）→ 按指令执行压栈（push）、出栈（pop）、逻辑运算 → 最终堆栈顶部为True则交易有效，否则无效。</br>
核心特点：无状态、指令简洁（仅支持基础运算和加密校验），确保交易验证高效、安全。</br>
2. P2PKH交易的脚本结构（核心！）</br>
P2PKH交易的验证逻辑，本质是“解锁脚本”与“锁定脚本”在堆栈引擎中的执行过程，两者联动完成校验：</br>
   - 锁定脚本（Locking Script）：绑定在收款方P2PKH地址上，格式固定为：</br>
OP_DUP OP_HASH160 <公钥哈希> OP_EQUALVERIFY OP_CHECKSIG</br>
        作用：规定“只有能提供对应公钥和私钥签名的人，才能花费该地址下的资产”。</br>
   - 解锁脚本（Unlocking Script）：由付款方提供，格式固定为：</br>
<私钥签名> <付款方公钥></br>
        作用：提供“证明自己有权花费资产”的凭证（私钥签名+公钥）。</br>
3. P2PKH堆栈执行完整流程</br>
1. 初始化空堆栈，先执行解锁脚本：将“私钥签名”“付款方公钥”依次压入堆栈；</br>
2. 继续执行锁定脚本，按指令逐步操作：     </br>
   - OP_DUP：复制堆栈顶部元素（付款方公钥），压入堆栈；</br>
   - OP_HASH160：弹出顶部公钥，计算其Hash160（SHA256+RIPEMD160），将结果压入堆栈；</br>
   - OP_EQUALVERIFY：弹出顶部两个元素（计算出的公钥哈希、锁定脚本中的公钥哈希），对比是否相等，不相等则交易无效；</br>
   - OP_CHECKSIG：弹出顶部两个元素（付款方公钥、私钥签名），用公钥验证签名有效性，将验证结果（True/False）压入堆栈；</br>
3. 执行结束，判断堆栈顶部是否为True：是则交易有效，否则无效。</br></br>

步骤1：导入所需库，定义核心工具函数</br>
导入实验所需库，定义3个核心工具函数（Hash160哈希、Base58Check编码/解码、签名/验签），支撑后续脚本生成和堆栈校验。</br>
步骤2：模拟堆栈式计算引擎类（核心模块）</br>
定义堆栈引擎类，实现“初始化、压栈、出栈、执行P2PKH脚本”核心功能，模拟真实比特币Script VM的堆栈操作。</br>
步骤3：生成付款方、收款方公私钥对及P2PKH地址</br>
模拟真实交易场景，生成付款方（Alice）、收款方（Bob）的公私钥对，生成收款方P2PKH地址（用于构建锁定脚本）。</br>
步骤4：生成P2PKH交易的解锁脚本和锁定脚本</br>
根据P2PKH脚本格式，生成解锁脚本（付款方提供）和锁定脚本（绑定收款方地址），为堆栈引擎执行做准备。</br>
步骤5：初始化堆栈引擎，执行P2PKH脚本并验证交易</br>
创建堆栈引擎实例，执行解锁脚本和锁定脚本，跟踪堆栈操作，判断交易是否有效。</br>
步骤6：调试与异常测试（可选，深化理解）</br>
修改脚本或签名，测试异常场景（如签名错误、公钥哈希不匹配），观察堆栈执行过程和交易结果，理解堆栈引擎的校验逻辑。</br></br>

实验结果分析</br>
1. 正常场景结果</br>
运行完整代码，控制台会输出“堆栈操作日志”，最终打印“P2PKH交易有效”，说明：</br>
- 堆栈引擎成功解析解锁脚本和锁定脚本，完成压栈、出栈、逻辑校验；</br>
- 私钥签名与公钥匹配，公钥哈希与锁定脚本中的哈希一致，交易验证通过。</br>
2. 异常场景结果</br>
执行步骤6的异常测试，会出现两种结果：</br>
- 错误签名：OP_CHECKSIG指令验证失败，堆栈顶部为False，交易无效；</br>
- 错误公钥哈希：OP_EQUALVERIFY指令对比失败，直接返回交易无效。</br>
3. 实验结论</br>
- 比特币P2PKH交易的执行，本质是堆栈式计算引擎对“解锁脚本+锁定脚本”的指令解析和堆栈操作；</br>
- 锁定脚本规定了资产花费的条件，解锁脚本提供了满足条件的凭证，两者联动实现交易安全校验；</br>
- 堆栈式引擎的“后进先出”特性，确保了脚本指令的有序执行，简洁且高效。</br>
